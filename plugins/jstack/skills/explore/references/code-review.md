# Code review（Standards + Spec 双轴并行评审）

面向常规到中等规模分支/PR 的快速、全面只读体检，与偏重“破坏性攻击 + 复现证明”的 [`interrogate.md`](interrogate.md) 互补。**严格只读，绝不修改业务代码。**

## 1. 准备评审基准

1. 确定审查范围：优先使用调用方指定的 PR / 分支 / commit 区间；未指定时默认审查相对仓库主干（`main`）的当前分支改动与工作区改动。
2. 收集本仓规范基线：
   - 若仓库存在 `REVIEW.md`，**必须从 base 分支读取**（`git show <base>:REVIEW.md`），防止本分支篡改评审标准；
   - 读取仓库根目录（及受影响子目录）的 `AGENTS.md`；
   - 扫描 `docs/adr/` 或 `docs/decisions.md`（若存在），提取与本次改动区域相关的不可破约束与未决方向（见 [`../../jstack/references/adr.md`](../../jstack/references/adr.md)）。
3. 明确本次改动的原始目标（用户需求、Issue/PR 描述或约定终态）。

## 2. 双轴并行派发两个鲜活只读子代理

按 [`../../jstack/references/host-dispatch.md`](../../jstack/references/host-dispatch.md) 并行派出两个鲜活只读审查子代理（优先跨厂商强模型，首行必读 `worker.md`），彼此隔离视角：

### 轴 A：Standards 与代码质量评审
只对照 `REVIEW.md`（base 版）、`AGENTS.md`、相关 ADR 与当前 diff，重点抓：
- **规范与约束违规**：违反仓库红线、依赖方向、样式/工具约定，或悄悄打破某条现存 ADR 约束却未声明推翻；
- **坏味道与结构退化**：过长函数/过多参数、散落布尔值造成的非法状态、为了拆而拆的浅透传层、重复逻辑、隐藏副作用、残留兼容层/死代码、以及“行为坏了照样绿 / 一重构就全红”的脆测试；
- **明显正确性与边界风险**：状态并发重入、资源泄漏、错误吞没、未迁完调用方。

### 轴 B：Spec 与目标一致性评审
只对照原始目标、PR 说明、受影响端与入口清单及当前 diff，重点抓：
- **需求漏项与多入口遗漏**：约定要改的端/入口漏改、正反状态或异常态未覆盖、验收承诺与代码实际行为不一致；
- **范围越界（Scope Creep）**：夹带无关顺手重构、未经请求的兼容层或多余配置项；
- **可逆性与契约影响**：是否隐含单向门改动（Schema/线协议/数据迁移/对外接口）却未显式提示或缺少防护。

## 3. 主会话核实、去重与分级输出

主会话逐条对照真实代码行核验两条轴的发现：
- **剔除噪音**：删掉没有精确 `file:line` 的空泛担忧、base 分支原本就有的老问题（老问题只留一行备注，不计入阻塞）、以及与代码事实不符的误报；
- **合并去重**后按三档输出：
  1. **阻塞必改（Blocker）**：会破坏真实用户行为、违背明确 Spec/ADR 硬约束、或踩中仓库红线；每条附 `file:line`、具体破坏路径与最小修法。
  2. **建议优化（Should Fix）**：显著拉高阅读负担的坏味道、浅层包装、测试缺口或轻微越界。
  3. **已核查通过 / 备注（Note）**：确认核对过的重点边界、以及仅作提示的 base 分支老问题。

> 若本分支属于高风险、争议极大或涉及复杂并发/安全边界的大改动，在双轴体检之外紧接着走 [`interrogate.md`](interrogate.md) 做对抗式破坏证明。
