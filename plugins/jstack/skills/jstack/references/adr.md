# ADR（架构决策与未决方向维护规约）

**第一铁律：代码库是“现状事实”的唯一真相。ADR 禁止复述事实，只写“代码里读不出来、且会约束未来改动”的东西。**

## 1. 只写这 2 类（决定未来事实走向的东西）

1. **会锁死或约束未来改动的决策（`accepted`）**
   - **排除了什么替代方案**：看似更顺手但明确不选的路，防止后来者或新 Agent “好心重构”踩回去；
   - **明确不做什么（Non-Goals）与不可破约束**；
   - **推翻条件**：什么前提变化时，这条决策应作废。
2. **尚未落成代码的未决方向与架构分叉（`proposed` / `open`）**
   - 已经定了大方向、或正卡在会影响后续多块代码怎么写的分叉口，但代码库里还看不到；
   - 写清当前倾向、阻塞点与待验证前提，避免过渡期写出和目标方向打架的代码；一旦落成代码事实或被否决，必须及时收口为 `accepted` 或 `superseded`，不留僵尸条目。

## 2. 严禁写这 3 类（全删，一字不留）

- **现状说明书**（技术栈介绍、目录树、模块职责总览——代码本身就是事实）；
- **实现流水账**（文件名清单、函数名、具体代码片段——一重构就腐烂）；
- **显而易见的标准做法**（没有真实替代取舍、读代码就能一眼看懂的常规实现）。

## 3. 落盘前门槛与唯一自检

同时满足三条件才建新 ADR：**难逆转（改动成本高或跨边界） + 缺少上下文会让人疑惑/误改 + 确实存在有竞争力的替代取舍（或影响未来代码的未决分叉）**。

写完后逐句执行反水文自检：

> **“删掉这句，后来者只读代码会不会做错决定？”**

答“不会”就删；整篇删完没剩几句，这篇 ADR 就不该建。

## 4. 目录与生命周期

- **标准多文件（默认）**：`docs/adr/NNNN-kebab-slug.md`（例如 `docs/adr/0001-relay-ciphertext-only.md`）。**懒创建**（没有真正满足门槛的决策前不建空目录）；编号只增不删。其他非 ADR 文档同样按职责分目录放（`docs/ops/`、`docs/guides/`、`docs/contracts/`），禁止平铺在 `docs/` 根目录。
- **单文件兼容**：仓库已有 `docs/decisions.md`（或小型项目偏好单文件表格）时，直接沿用原文件维护，不强行拆目录。
- **状态流转**：`proposed` / `open`（未决方向）→ `accepted`（已定决策）→ `superseded by ADR-NNNN` 或 `deprecated`（已推翻/废弃）。
- **只追加不覆盖历史**：推翻旧决策时，新建一条新 ADR 说明新决定，并在旧 ADR 顶部仅改状态为 `superseded by ADR-NNNN` 并补一句触发的推翻条件；`proposed` / `open` 一旦落地成代码或被放弃，必须在同一 PR 内同步收口状态。

## 5. 极简模板（通常 10–25 行）

```markdown
# ADR-NNNN: <一句话说清决策或未决分叉>

- 状态：`accepted` | `proposed` | `open` | `superseded by ADR-XXXX`
- 日期：YYYY-MM-DD

## 决定 / 未决方向
1–3 句话直说定了什么（或正悬而未决的分叉与当前倾向），以及为什么。

## 排除的替代方案（按需）
- **方案 X**：为什么明确不选。

## 代价与不可破约束（按需）
- 接受了什么代价；后续代码绝不能打破哪条边界（或 Non-Goal）。

## 推翻 / 收口条件（按需）
- 什么前提改变时推翻此决策；若为 `proposed` / `open`，写清什么信号触发最终定案。
```

## 6. 全流程联动分工

维护 ADR 是研发流程的副产品，不单设独立流程：

- **`explore`（读 & 溯源）**：[`why.md`](../../explore/references/why.md)、[`blast-radius.md`](../../explore/references/blast-radius.md) 与 `investigation.md` 查动机和影响面时，优先扫 `docs/adr/` 或 `docs/decisions.md`，避免把刻意约束误判成历史遗留。
- **`implement`（查栅栏 & 拍板起草）**：[`architect.md`](../../implement/references/architect.md) 及 `feature.md` / `refactoring.md` 动核心模块前先核对现存 ADR（冲突时必须明说是否触发推翻条件）；拍板踩中门槛的取舍或未决方向时，顺手起草极简 ADR 随本次 PR 落盘。
- **`ship`（收口落盘 & 注释升格 & 复盘沉淀）**：[`no-comments.md`](../../ship/references/no-comments.md) 清注释时将跨模块架构约束升格进 ADR；`opening-a-pr.md` 提交前补齐新增/变更/收口状态；[`retro.md`](../../ship/references/retro.md) 复盘时把无法机械化的架构级取舍沉淀进 ADR。
