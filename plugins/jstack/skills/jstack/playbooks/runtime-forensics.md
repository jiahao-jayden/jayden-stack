# Runtime forensics（现场运行诊断）

**你对诊断结论负责。给活着的进程采样和插桩，绝不靠读源码脑补。** 交付物是带实证的诊断报告，不是代码补丁。

1. **在真实运行面上抓取活信号**：
   - 按症状采集真实运行态产物：CPU 飙升抓 CPU profile，内存泄漏抓 heap snapshot，界面卡顿/闪烁抓 CDP trace 或帧耗时记录，进程卡死抓线程堆栈/日志。必须是真产物，不靠猜。
2. **把大产物压缩成确凿证据**：
   - 定位热路径函数、泄漏对象到 GC Root 的完整引用链、或无输入却空转的循环。
   - 几十 MB 的 profile/snapshot 派只读 `scout` 去解析提炼，只把浓缩后的关键发现带回主会话（保护上下文窗口）。
3. **先验证机理，再相信它**：
   - 通过实时调试通道（CDP eval、临时探针、热补丁或日志埋点）在运行态低成本验证你的因果假设确实触发/消除了现象。
4. **精确映射回源码**：
   - 给到精确 `文件:行号`、符号名，以及真正分配内存、调度或死循环的那一行。
5. 吞吐检查点只留一行：`吞吐检查点：n/a，只读现场诊断`。

**回复要求**：抓了什么信号、提炼出的核心发现、怎么在运行态证明了机理、精确源码位置、采样产物文件路径。除非用户明确要求，否则先不改代码；查清根因后转入 **Bug fix** 或 **Perf issue**。
