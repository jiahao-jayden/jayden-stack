# Autopilot-stack（并行做完一批 PR 后交接）

完整沿用 [`autopilot-full.md`](autopilot-full.md) 的并行构建与独立验证纪律，但**绝不执行合并**——全部做到“已验证且绿灯”后统一交回给用户决定何时合并。

1. **替换第 5 步，在「已验证（verified）」停下**：
   - 当每个 PR 在当前 head 上拿到独立验证通过且 CI 全绿后，立刻停止并向用户交接。
   - 交接之后，未经用户明确指示，任何代理不得再向这些分支推送。若使用定时巡检，每轮提示词里必须显式引用本文件以死守“禁合并”规则。
2. **仅在存在真实代码依赖时叠栈（Stack）**：
   - 这是对 `autopilot-full.md` 第 3 步“全部基于主干并行”的唯一例外：只有当 PR B 确实建立在 PR A 的代码之上时，才把 PR B 的 `--base` 设成 PR A 的分支（见 `opening-a-pr.md`）。
   - 栈底 PR 变基到主干，上层 PR 变基到其父 PR 分支。下层 PR 产生新 head 时重整上层 PR；若重整后某 PR 的 `git patch-id` 未变，沿用其既有验证结论（见 `shipping.md` 第 3 步）。

**回复要求**：列出全部 PR（含栈依赖顺序）、各自最新 head SHA、独立验证结论、CI 状态、待用户审核的重点项与全部 PR 链接（明确标出均未合并）。
