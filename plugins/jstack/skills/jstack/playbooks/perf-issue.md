# Playbook：性能优化（Perf Issue）

**拿前后实测数字说话。不先测基准就不改代码，不靠读源码脑补瓶颈。**

1. **先抓可复现的基准数据**：在真实的运行环境与目标设备上采集优化前的耗时、帧率、内存、体积或 trace（明确环境、样本数与运行命令，确保前后口径一致）。
2. **顺着真实数据定位瓶颈**：按从最省钱到最贵的「七条性能口诀」依次考虑，前一条够达标就停：
   1. **干脆不做**：没人用的结果直接砍掉，比把它算快强十倍。
   2. **做一次就别重复做**：缓存、记忆化、避免无意义重算或重渲染。
   3. **少做一点**：降频、裁剪数据量、只算可见区域。
   4. **晚点再做**：懒加载、延后到真正需要时。
   5. **趁用户不注意时做**：空闲预处理、预取。
   6. **并发着做**：拆掉无必要的串行等待。
   7. **用更便宜的办法做**：换数据结构、换算法或换底层实现。
3. **一次只验一个改动**：按可验证切片逐个实施，每改完一个就用同一口径重测一次，防止多个改动互相遮盖正负效应。连续三轮没有实质收益或引入回退时立刻停下复盘。
4. **验证正确性与前后对比**：
   - 核对优化后没有破坏任何行为边界或 UI 观感；
   - 对比优化前与优化后的真实数字与差值；口径不一致或结果“看不出明显变化”不能算通过，如实标出。
5. **把测量口径与前后数字写进提交/PR 并收口**：按约定转入 [`ship.md`](ship.md)。

**回复必含**：测试环境与命令、优化前基准、优化后结果、变化幅度、正确性验证结果。
