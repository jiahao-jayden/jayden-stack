# Autopilot-full（并行把一批独立 PR 做到合并）

**你掌管裁决与总盘，不亲自包揽每个 PR 的代码。每个 PR 配一名独立负责人一路从开发带到合入；而代码未经“没写过它的独立验证蜂群”证明前，绝不允许合入。**

一条验证结论只覆盖一个补丁，一次绿 CI 只覆盖一个 head。每个 PR 在代码就绪时跑一次完整验证蜂群，只有大改动或新行为才重跑完整蜂群；每个新 head 都必须拿到自己的绿 CI。

1. **操作者的红线门禁永远优先**：
   - 授权范围只涵盖本次队列中的条目；队列之外的 PR、以及用户明确标明由其亲自把关的条目，最远只做到 `merge-ready` 就停下。用户让你“先出方案”不等于授权直接合并。
2. **每个 PR 派一名独立负责人（Owner），且过程随时可接管**：
   - 先确定一次托管平台（默认 `gh`，Origin 仓库用 `origin pr`，不依赖 `gt`）。
   - 每名负责人各自在独立分支/worktree（或云端代理环境）推进：开发 → 按 [`opening-a-pr.md`](opening-a-pr.md) 尽早提 PR 让 CI/审查尽早跑起来 → 自清冗余与注释（`no-comments`） → 变基到最新主干并上报 `code-ready` head → 真实自证 → 按 [`babysit.md`](babysit.md) 盯绿 CI 与清评论 → 等第 4、5 步全部放行后再合并。
   - **假设任意子代理随时会挂**：开工不久就推送分支并在共享轨迹日志中按 **show-me-your-work** 记下决策行与子代理 ID、状态及超时阈值，每完成一个切片立即推送，确保随时可换鲜活负责人无损接手。只允许用 `--force-with-lease=<上次自推SHA>` 推送自己的分支，发现分支上有他人推送立刻停下上报。
3. **所有负责人全部基于主干并行，默认不叠栈**：让每个 PR 都能独立落盘，互不拖累。
4. **独立蜂群验证一次（Swarm-verify）**：
   - 在负责人上报 `code-ready` SHA 时，按 **swarm** skill 派出**未参与编写该 PR 的独立验证者**：重跑门禁、在真实运行面上按用户路径实测（优先项目 `verify-*` skill）、审查 diff。
   - 没有真实运行面验证通道、或未核查负责人自证凭据前，结论不算通过——**绝不轻信负责人自报绿灯**。
   - 仅因“当前 head 可复现的失败、真实用户会碰到的 Bug 或本 PR 写坏的文档”阻塞；主干原本就有的老问题记入 follow-up，不阻塞本 PR（除非本 PR 复制或新触发了它）。
   - 后续若是单纯 rebase、解冲突或微小修补，用单个验证者复核新 head 即可；纯措辞修改免重跑。
5. **只合入在最新主干上验证过的内容**：
   - 绿 CI 本身不构成合并授权，必须「独立验证通过 + 最新主干兼容 + 绿 CI」。
   - 合并前先 fetch 主干判断主干新提交是否会影响本补丁：
     - 存在冲突、触碰了相同文件或改了 CI 规则 → 必须 rebase 并等新 CI 全绿；
     - 仅锁文件两边都改了，且合并结果上冻结安装通过且受影响包版本一致 → 无需盲目重跑整套 rebase；
     - 主干改了本补丁的调用方或上游依赖 → 在合并结果上重跑对应检查通过后再合；
     - 若合并准备阶段主干推进迫使连续第 3 次 rebase，停下报总控统一排程。
   - 合入后按 [`shipping.md`](shipping.md) 读回确认 `MERGED` 且目标为主干。
6. **总控层的巡检与门禁**：
   - 任何放宽检查门禁的改动（调高预算、加白名单）必须由验证者给出证明并经总控复签；绝不允许关闭或软化检查，绝不绕过平台强制人工审批。
   - 长跑期间定时巡检所有子代理的**真实副作用**（是否推送、是否新增轨迹行、是否有真实进展），不轻信“正在思考”的空状态文本；确认卡死立即替换为鲜活代理，不干等。
7. **收到用户叫停信号立即全域冻结**：向所有负责人下达零写入指令，各自汇报当前停靠点并保持现场。

**回复要求**：按 PR 列表汇总每个 PR 的状态、独立验证结论、已合入列表与读回确认、复签记录、等待人工门禁项、遗留 follow-up 以及全部 PR 与轨迹日志链接。
