# Playbook：跨会话与跨工具交接（Handoff）

**核心原则：停下来时不丢状态，接手时不重做已验证过的工作。适用于同工具开新会话，也适用于 Cursor ↔ Codex 之间接力。**

先判断当前是「暂停交接」还是「接手继续」：

## A. 安全暂停（Pause）

当上下文快满、要切去另一个工具（如从 Cursor 切到 Codex），或暂告一段落时：

1. **先把工作区收到干净状态**：
   - 把当前已完成的干净阶段打成正常 commit；
   - 若还有进行中的半成品改动，先跑一下快速检查确认没有破坏明显语法，然后打一个 `wip: <简短进展>` 提交（或按用户要求保持工作区并写清 `git status`），不要留下无人看管的后台 dev server 或残留临时进程。
2. **输出一段可直接复制给下一会话的精简交接块**（控制在一屏内，不写流水账）：
   - **目标与约定终态**：要做成什么、最终要收到哪一步、用户指定的设备/运行方式是什么。
   - **当前锚点**：仓库路径、分支名、最新 commit SHA、工作区是否干净（若有未提交文件列出路径）。
   - **已完成且有证据的部分**：哪些端/入口已经跑通、跑过什么命令/实测结果。
   - **尚未完成与踩过的坑**：下一步第一件要做的事、已经试过但失败的死路（避免下一会话重踩）、任何已知阻塞或待确认决策。

## B. 接手继续（Pickup）

当你拿到一段交接摘要、或进入一个已有半成品分支的新会话时：

1. **先核现场，再信摘要**：快速执行 `git status`、`git branch --show-current`、`git log -n 5 --oneline`（以及必要的 `git diff --stat`），确认仓库当前状态和交接说明一致。
2. **信任已验证的进度，不推倒重做**：不要把前一个会话已经 commit 并验证通过的工作从头重查一遍；除非现场检查发现不一致或有明显回退。
3. **先把剩余清单放进 todo，继续直奔终态**：明确告诉用户“我已接手，当前在 `<branch>@<sha>`，接下来先做 X，目标收到 Y”，然后直接按对应 Playbook（`build` / `ship` 等）推进。
