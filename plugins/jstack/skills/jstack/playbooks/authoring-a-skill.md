# Authoring a skill（写或修改 Skill）

**你对这个 Skill 的锐度与可执行性负全责。**

1. 遵循平台标准的 Skill 规范（具备清晰 YAML frontmatter：`name`、`description`；清晰触发场景、步骤、边界与输出格式）。
2. 逐项校验结构完整性：
   - frontmatter 包含准确 `name` 与高区分度 `description`；
   - 所有引用的相对路径文件、脚本、跨 skill 链接全部真实存在且可执行；
   - 若涉及插件市场/清单 JSON，同步校验 JSON 语法。
3. 如果改动涉及结构化流程、脚本或触发链，跑真实测试用例或盲评验证（见 `eval.md`）；纯文字措辞微调可跳过重型测试。
4. 按约定走 [`opening-a-pr.md`](opening-a-pr.md) 或提交推送。

**写作铁律**：
- 拿不准要不要留的句子直接删；**只保留会改变 Agent 决策的文字**。
- 直接下指令“做什么”，少讲大道理；只有在规则脱离解释会让人误解时才补一句原因。
- 把事实锚定到结构化来源（类型、脚本、配置、`README`），不要在 Skill 里手工复述容易腐烂的清单。
- 复用其他 Skill 直接按路径引用，不要复制粘贴重述。
- 发现某个高频工作流反复出现却还没沉淀，主动提议新建 Skill。

**回复要求**：Skill 摘要、核心设计取舍、校验与实测记录。
