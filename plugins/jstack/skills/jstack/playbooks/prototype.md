# Prototype（用原型做决定）

**你拥有设计决策，不拥有这段代码。原型是用完即扔的实验工具；选定后再走 Feature 做正式开发。**

这是唯一一个「懒惰协议的最小改动」和「高代码质量要求」全部反转的剧本：速度优先于打磨，代码质量无关紧要，不做长篇规划。真正的严谨体现在**用最低成本选对设计**——主动给出用户没想到的备选方向，不合适就整套扔掉重画一套。

1. **锁定原型要拍板的具体问题**：
   - 到底要决定哪种布局、交互、动效、信息密度？还是技术分叉上的哪种行为、时序或算法？
   - **没有明确待拍板的决策就不做原型**，直接转 **Feature**。
2. **设计空间开放时先收参考**：
   - 方向还没定死时，先查成熟产品先例，整理一版简明参考方向（风格、配色、布局、交互范式）让用户挑大方向再搭原型；方向已明确就直接跳过这步。
3. **在隔离临时目录极速搭建抛弃式原型**：
   - 放在独立临时目录，**绝不污染正式生产源码树**。
   - 视觉/交互决策：用原生 HTML/CSS/JS 或最轻的可渲染技术栈 + 热重载本地预览；
   - 行为/时序决策：用最小独立脚本直接跑出对比现象。
   - 不引入生产框架、不写单元测试、不做工程抽象。
4. **多备选方案塞进同一个切换器**：
   - 对比 2–3 个方案时，在同一个界面里放切换按钮或快捷键，每个方案标清名称，让用户一眼切换横评（落地的「穷尽设计空间」）。
5. **在对应运行面上真实观察**：
   - 视觉/交互决策：真实打开、操作正反状态（展开/收起、遮挡、动效手感）并截图留证；
   - 行为/时序决策：直接打印真实耗时、事件序或渲染观测结果。这里的“观测本身”就是测试，不写死板断言。
6. **展示权衡、证据与明确推荐**：
   - 产出是**决策结论 + 抛弃式临时原型路径**，不是可上线代码。用户选定方向后，交给 **Feature**（跨模块先过 `architect`）按正式骨架**从零重写**；**严禁直接把临时原型里的脏代码复制进生产源码树**。

**回复要求**：探索了哪些方案、实测证据（截图或观测输出/耗时）、各方案权衡、你的明确推荐、临时目录路径，并**明言该原型是抛弃式的**。
