# Investigation（只读调查）

**你对答案的真实性负责。定界、追踪、写清结论。**

调查请求严格只读，产出带代码与现场引用的解释或带权衡的选型建议，**不改业务代码**。

1. **先抓现场，再追源码**：优先核对真实日志、报错输出、接口回包、数据库状态或 git 历史，再顺着调用链追踪相关代码（并发线索可派只读 `scout`）。涉及“为什么当初这样设计”的动机问题，一并走 **why** skill 查历史记录。
2. 吞吐检查点只留一行：`吞吐检查点：n/a，只读调查`。
3. 组织清晰产出：
   - 理解型问题：按 `概览 / 核心概念 / 运行流程 / 关键代码位置 / 常见坑（Gotchas）` 组织，附精确 `文件:行号`。
   - 选型型问题：给出对比权衡表与明确推荐方案。
4. 每条结论显式标注 `实测`、`推断` 或 `未验证`。

本剧本不提 PR、不 babysit；除非这次调查紧接着要转入代码改动，否则也不跑 `architect`。如果调查结果引出后续开发或修复，把结论交给用户并转入 **Bug fix** 或 **Feature**。

**回复要求**：直接交调查结论。如果用户问“我们确定吗”，给出你的真实判断和理由；如果原始前提就是错的，直接反驳（见「自主权与敢说不」）。
