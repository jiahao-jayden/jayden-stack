# Feature（实现新行为）

**你拥有设计与验收权。规划、定边界、审 diff、亲自验真实环境；具体编码按需委派给子代理，始终握紧方向盘。**

1. **先摸清受影响子系统与多入口清单**：
   - 派只读 `scout` 追踪相关模块现状、已有依赖和同类模式（优先复用仓库已有库与成熟模式）。
   - 把用户点名的全部端与入口（桌面端、移动端、侧栏、弹层、设置页等）以及本次约定的终态（本地提交 / PR / CI 绿 / 合入 `main` / 发版）写进 todo。
2. **跨边界先跑 `architect` 定骨架**：
   - 先查相关 `docs/adr/` 或 `docs/decisions.md`（见 [`../references/adr.md`](../references/adr.md)），核对不可破约束与未决方向；若新方案推翻旧 ADR，明说触发条件并计划同步标旧 ADR 为 `superseded`。
   - 先确定数据形状、状态唯一归属与领域模型（用显式状态机替代散落布尔值，用查表/注册表替代冗长分支，用强类型模型消除重复假设），再写业务逻辑；若本次是由 `prototype.md` 拍板转入，必须按正式骨架重新实现，严禁直接照搬原型临时代码。
   - 若拍板了满足门槛的架构取舍或未决方向，顺手起草极简 ADR 随本次 PR 落盘。
3. **把「吞吐检查点」写成四条 todo（强制，不可省略）**：
   即使某项确实不适用（如单文件小改动），也要保留该条并写 `n/a: <具体原因>`，禁止直接删掉不写：
   - **阻塞前置步骤**：哪些基础类型/共享原语/门禁必须在并发前先落好。
   - **独立并行工作流**：互不重叠的文件、服务或层级如何并发；共享写入怎么串行。
   - **共享可变状态**：默认按「先拆分再串行化」切开目标，只在真不变量处串行。
   - **最小安全拆解**：如果单 worker 最合理，写明为什么。
4. **委派编码并把控实现质量**：
   - 派 `worker`（首行读 `worker.md`），给清精确文件路径、第 2 步定好的数据形状与领域模型、严禁保留旧兼容层、以及明确验收标准。
   - 当实现存在多种截然不同的有效形态（错误处理策略、抽象边界、状态组织）难以拍板时，改走 [arena](../../implement/references/arena.md) 并发赛马 + 跨厂商裁判选出最佳底座再手工嫁接，**不要跳过偷懒**。
   - 改动了共享原语时，同步迁完所有调用方并删掉旧接口，逐个验证。
   - 状态机、协议编解码、解析器或复杂数据转换优先补属性测试（Property Test，如 `fast-check` / `proptest`）或行为级测试。
5. **在真实运行面上端到端验证**：
   - 严守用户指定的设备与运行方式（热更新、真机、禁模拟器），有项目 `verify-*` skill 优先用它驱动。
   - **UI/交互改动必做正反检验**：展开与收起、打开与关闭、浮层/菜单不遮挡按钮、空态/加载态/报错态；逐一跑通第 1 步的多入口清单。“看不出结果”或换错运行面都不算通过。
   - 同一问题累计 3 轮修不过立刻停下带证据找人讨论。
6. **整理成小而有序的可验证提交**：
   - 按「拆成可验证切片」整理提交序列，每片自洽可测，后续改动按依赖叠加。
7. **收口前按风险过只读评审**：
   - 常规到中等规模改动可过 [code-review](../../explore/references/code-review.md) 做 Standards + Spec 双轴并行体检；
   - 中高风险或争议改动收口前过 [interrogate](../../explore/references/interrogate.md)（及按需 [blast-radius](../../explore/references/blast-radius.md)），用跨厂商只读评审提前打爆盲区（若仓库 base 分支有 `REVIEW.md`，从 base 分支读取作为基准）。
8. **执行 [`opening-a-pr.md`](opening-a-pr.md)** 并一路做到约定的终态。

> 耦合协作规则：紧密耦合的单功能/单迁移交给单一负责人带着检查点在内部做完前置后再并发；主会话层的并发只用于产出独立工件的切片（审计、跨子系统调研、竞品实验）。阶段切换时重写检查点；遇阻优先开鲜活负责人，不反复打断同一个旧上下文。

**回复要求**：做了什么、为什么选这个设计（备选方案用对比表）、吞吐检查点、多入口逐项实测结果、遗留待定项。
