# Bug fix（复现并修复缺陷）

**你对根因与回归证明负全责。掌舵规划、审查 diff、亲自验收；具体侦察和编码按需委派给子代理。**

保持科学方法：**发出去的每一行代码都必须能追溯到运行态证据。**“以防万一可能有用”的防御补丁只是猜测，不是修复，绝不合入。一旦新证据推翻了某个假设，把该假设引出的改动一并回退。只交付证据证明必需的最小改动，不多写一行。

1. **先自己复现，并抓现场证据**：
   - 在与问题匹配的真实运行面上自己复现（优先用项目专属 `verify-*` skill，严守用户指定的设备与运行方式，如热更新、真机、禁模拟器）。
   - 绝不轻易让用户替你复现——只有当你已把控制手段用到极限且给出明确理由说明当前环境触达不到时，才请用户协助。如果直接触发不了，就构造触发条件、收紧参数或加临时观测日志直到稳定复现。
   - 同时圈出受影响的全部端与入口（桌面端、移动端、侧栏、弹层、服务端等），列入 todo 清单。
2. **二分法缩小根因**：
   - 列出候选假设，结合受影响子系统追踪与 [why](../../explore/references/why.md)（查回归历史）逐一证伪，直到只剩唯一站得住脚的机理。
   - 每一步选能砍掉最大问题空间的切分点，拿真实运行数据（日志、状态快照、临时埋点输出）排除假设，绝不靠猜。
   - **质疑前提与三轮熔断**：同一假设连续修 2 次未过，立刻按「质疑前提」停手直接测前提；同一问题累计 3 轮仍修不过，立刻停下带完整复现、报错与已排除假设回报用户。
   - 必须先用运行态证据证实存活的根因机理，再进入第 3 步。
3. **设计并实施最小修复**：
   - 修复跨函数或模块边界时，先跑 **architect** 定形状；复杂或有争议的方案先过 **interrogate**。
   - 委派给 `worker`（首行读 `worker.md`）时，给清精确文件路径、根因机理、不留旧兼容路径的要求与验收标准。
4. **在同一个真实运行面上验证通过**：
   - 原先的复现路径现在必须稳定通过；“看不出结果”或换了别的运行面测试不算通过，必须如实标出。
   - 单元测试只能证明分支行为，不能替代真实环境里 Bug 已消失的证明。
   - 若涉及 UI/交互，正反状态全测（展开+收起、打开+关闭、浮层不遮挡按钮），并逐一核对第 1 步列出的全部端和入口。
5. **按“红灯在前、修复在后”组织提交**：
   - 只要该 Bug 存在低成本的本地测试路径，走 [tdd](../../implement/references/tdd.md)，让 git 历史里“失败回归测试”落在“修复代码”之前（或同一组清晰可验证切片中）。如果测试代价过高或强依赖重型集成环境，不要造脆测试，如实说明改用了何种真实回归检验。
6. **按约定收口**：执行 [`opening-a-pr.md`](opening-a-pr.md) 及后续约定终态（推送 / CI / 合并）；若属于疑难 Bug 或反复踩过的同类坑，收口时顺手按 [retro](../../ship/references/retro.md) 给出「问题 → 根因 → 解法 → 防线沉淀」，优先固化进架构/类型/Lint/测试，绝不往 `docs/` 里新丢 `*-retro.md` 长文。

**回复要求**：坏了什么、根因是什么（附 `文件:行号` 与现场证据）、改了什么、逐入口验证结果，并**原样粘贴先失败再通过的复现输出**。
