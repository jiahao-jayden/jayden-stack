# Visual parity（验证外观一致）

**你对像素级一致负全责。基线就是唯一规格书，绝不篡改基线。** 一致性靠图像 diff 证明，不靠肉眼扫一眼觉得“差不多”。

1. **先锁定基线，再动第一行迁移代码**：
   - 搭建视觉回归截图脚本，把当前组件在各个状态（默认/hover/展开/收起/禁用/深浅色等）下的基线图完整截下来；若是比对两套实现，同时截目标图。
   - **没有基线，就不允许宣称一致**。这是阻塞前置，不是事后补拍。
2. **声明并死守反作弊条款**：
   - 严禁修改比对脚手架放宽阈值；
   - 严禁篡改基线截图；
   - 严禁为了凑过 diff 扭曲组件结构。
   - 如果发现基线本身就是错的，立刻停下向用户确认，绝不私自重录基线。
3. **一次迁一个组件，按需并行**：
   - 共享基础原语先作为阻塞阶段迁移完；
   - 之后每个组件由独立负责人落在各自 git worktree 并行迁移（先拆分再串行化）。
4. **用图像 diff 逐个死磕到零偏差**：
   - 在真实运行面上对每个组件跑图像 diff。**非零偏差就是失败**，必须追查具体像素差异原因并迭代修复直到 diff 归零（同一组件连续 3 轮卡住立刻停下带 diff 图求助）。
5. **按单个组件或安全小批次走 [`opening-a-pr.md`](opening-a-pr.md)**。

**回复要求**：迁移了哪些组件、每个组件的图像 diff 结果、基线脚手架与截图路径、还剩哪些未迁。
