# Pause safely（暂停并留下继续点）

**你对一次干净利落的停靠负全责。留下的检查点必须让一个完全冷启动的新代理（Cursor 或 Codex）一眼接手、零信息丢失。**

> 触发边界：只在用户明确要求暂停、切换工具或上下文即将耗尽时执行。若用户说过“别停 / 一路做完 / 睡觉前跑完”，不要自行暂停。

1. **在安全原子边界停下**：
   - 收完当前这个最小的原子步骤，或把写到一半的半成品干净撤回。
   - 不开启任何新任务，取消仍在跑的嵌套子代理，清理本次拉起的临时后台进程。
2. **暂停时不执行任何不可逆动作**：
   - 不新建 PR、不合并、不部署；除非此前该分支本就已推过远端，否则不主动 push。
3. **把现场状态落盘持久化**：
   - 将当前未提交改动整理为一个清晰的 `wip: <简短进展>` commit 落在当前分支，防止切换会话/工具时丢失工作区。
   - 如果当前代码树处于编译不过或测试未绿的半成品态，在 commit body 里用**一行直白写明**。
4. **把续接说明写到上下文之外**：
   - 写清：原始目标与约定终态（含设备/运行方式要求）、当前正在做什么、已完成且有实测证据的部分、当前分支与最新 SHA、精确的下一步第一动作、关键文件路径、以及已经试过且失败的死路（避免下一会话重踩）。
   - 如果需要抗上下文压缩，把这份续接说明落成文件（如 `/tmp/<slug>-resume.md`）；若本次已有 `show-me-your-work` 决策日志，直接指向该日志路径，不重复抄写。

**回复要求**：当前停在循环的哪一步、哪些内容已落盘（给路径，不倾倒整段 diff）、打出的 commit 与工作区是否干净，以及下次恢复时要做的第一件事。明确标注这是一次暂停，不是最终结案汇报。
