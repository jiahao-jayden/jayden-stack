# Session pickup（接手其他会话）

**你对续接点的准确性负全责。读清前序轨迹，信任已验证进度，绝不从头重做。** 同样适用于同工具新会话，以及 Cursor ↔ Codex 之间接力。

1. **先定位并读取前序轨迹**：
   - 来源可能是当前工作区 `agent-transcripts/` 下的历史记录（注意：**绝不跨项目扫描无关目录**）、前序会话给的交接文件/摘要、云端代理链接，或已经推送的分支。
   - 先看元数据与末尾几轮消息，再倒推关键决策点。超长 transcript 派只读 `scout` 提炼成精简时间线带回主线程（保护上下文窗口）。
2. **用真实 git 状态重建现场**：
   - 跑 `git status`、`git branch --show-current`、`git log -n 10 --oneline`、`git diff --stat <base>...HEAD`，核对所在分支/worktree、已落盘提交、未完成 todo 和前序决策。
   - 把前序轨迹当作权威输入，克服“我不放心，我要重新调研一遍”的冲动。
3. **对比“已完成”与“待完成”，精准定锚续接点**：
   - 列出已经落地并有证据的部分，指出确切续接点；**不要重跑前序已经跑通的复现或重做已完成的工作**。“让我从零全部重查一遍”等于把前序轨迹当废纸。
4. **切入对应 Playbook 继续推进**：
   - 明确判断下一步裁决：继续编码（转 `feature`/`bug-fix`）、推进已就绪方案（转 `opening-a-pr`/`shipping`）、复核或推翻前序结论、还是复盘一次失败运行。
   - 交接剧本到此结束，剩余步骤交给路由到的主 Playbook 接管。
5. **收口前针对原始目标在真实产物上做终态复核**：
   - 接手阶段不重做中间工序，但最终交付前必须按「证明它真的能工作」对照原始目标与约定终态在真实产物上核验——前序的自称通过不能替代最终交付核验。

**回复要求**：前序停在哪一步、你直接继承了什么 vs 重做了什么（理想情况为零重做）、当前确切续接点，以及接下来推进的结论。
