# Figure it out（大任务自建工作流 + 科学实验环）

当任务规模大、跨度广、没有任何单一现成 Playbook 完整贴合时，先为它**设计专属工作流**。在动第一行业务代码前，第一个交付物就是这套可审计、可按科学实验推进的阶段剧本。

## 启动

先开 todolist：第一项为查阅 `../../jstack/references/principles.md`；随后把下面五个阶段加进 todolist。

## Phase A：定界与严苛度（Frame）

先查清现场，再立军令状。写不出以下三条就不开工：
- **可证伪的完成谓词**：怎么客观证明全部做完（证明它真的能工作）；
- **量化范围**：大致涉及多少单元、工作量级，以及摸底已经发现的阻塞点；
- **严苛度分级（宁高勿低）**：不可逆的单向门和高爆炸半径步骤设重门禁；可逆低风险步骤放轻。**严谨靠门禁和实测产物，不靠嘴上说“更认真一点”**。

对于预计耗时长的大工程，把定界与权衡先呈现给用户确认一次检查点再开跑。

## Phase B：设计专属工作流（Design the workflow）

- **按风险最高、最不确定的切片排在最前面**，拆成可独立落盘的原子单元；**脚手架和验证工具永远先于业务功能**（底层思考）。
- **先搭验证脚手架并抓改造前基线**：让后续每一片检查都能直接读出 `旧值 vs 新值`。
- **单向门架构决策过 `architect`（必要时 `arena`）**：机械重复且形状已明朗的活不要过度设计（懒惰协议）。
- **规划并发边界**：只在天然接缝处并发，每个 worker 分配独立 worktree/分支（先拆分再串行化），不过度扇出。
- **把设计好的阶段清单写下来**：这就是给用户审阅的蓝图，把具体步骤插进 Phase C 和 Phase D 之间的 todolist 中。

## Phase C：科学实验循环（Run the loop）

把每个原子切片当成一次独立实验：**写下假设 → 做最小改动 → 在真实产物上跑验证谓词 → 有效推进就保留提交，没推进就全量回退**。每做完一片立刻验收，绝不攒到最后一起验。

- **看真实产物，绝不信自称通过**；如果某步通过得过于轻松，先怀疑观测脚本有没有测空。
- **给委派工作配独立裁判**：如果 worker 钻空子绕过了门禁，立刻重置并收紧契约；如果门禁本身写错了，单独修门禁，绝不绕过门禁。
- **三值结论**：每片只能给 `VERIFIED`、`NOT VERIFIED` 或 `INCONCLUSIVE`；`INCONCLUSIVE` 不算通过，绝不掩盖负面结果。
- 同一切片连续 3 轮卡死立刻熔断停下上报。

## Phase D：全程维护决策审计轨迹（Audit trail）

按 [show-me-your-work](../../ship/references/show-me-your-work.md) 每落完一片就实时写一行 TSV 决策日志（绝不拖到结束补写）。大工程通常把这份决策轨迹一并提交进 PR，让审阅者离开几小时回来也能顺着轨迹信任整份 diff。

## Phase E：端到端总验与结构化沉淀（Verify and hand back）

- 在真实产品运行面上（不只在脚手架里）对照 Phase A 的完成谓词做全链路总验；
- 凡是过程中反复踩过的同类纠偏，按 [correct](../../ship/references/correct.md) 固化为门禁、Lint、类型或脚本。

**回复要求**：你设计的工作流剧本、严苛度级别及理由、决策轨迹路径、对照完成谓词的逐项验证结果，以及仍开放的事项。
