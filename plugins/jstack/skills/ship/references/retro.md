# Retro（问题沉淀、棘轮固化与 `docs/` 熵减自整理）

在以下三种时机触发（零盘问，直接输出结论与动作）：
1. 用户问**“你发现的是什么问题 / 怎么解决的 / 沉淀一下 / 复盘一下”**；
2. 用户要求**“整理 `docs/`”**或清理过时文档；
3. 完成一次非平凡开发、疑难 Bug 修复或合入 PR 收尾后。

**铁律：沉淀的目的是“以后不再犯错 + 降低仓库熵增”，绝不是在 `docs/` 里新拉一篇没人看的 `*-retro.md` 长文。**

## 为什么必须同时看两份证据

- **成品证据**（`git diff`、PR 评审评论、CI/测试报错）：暴露最终代码里的薄弱点；
- **过程证据**（本轮会话上下文 / transcript 里的反复搜错文件、跑错命令、人工打断纠偏、中途否决的方案）：`git diff` 看不到弯路，只有扫过程才能揪出误导文档、工具缺口与隐性约束。

## 一、问题复盘与沉淀四段式（先说清，再落点）

当复盘一次具体问题或任务时，先用 3–6 行讲透，再按严格优先级决定沉淀落点（**能用高层防线绝不写文档**）：

1. **发现了什么问题与根因**：精确 `file:line`、现场运行证据、以及为什么原本没拦住。
2. **怎么解决的**：最小根因改动，以及中途排除了什么看似可行但走不通的方案。
3. **棘轮落点（按防线层级从高到低，严禁凑数）**：
   - **L1 机械化防线（最高优先）**：按 [`correct.md`](correct.md) 优先级固化进 **架构消灭 > 类型/Lint 拦截 > 行为测试**，并用本轮真实出错案例验过红灯拦截；
   - **L2 架构决策 / 未决方向**：仅当踩中 [`../../jstack/references/adr.md`](../../jstack/references/adr.md) 三条件门槛（难逆转 + 缺上下文会误改 + 真实替代取舍或未决分叉）时，写 10–25 行进 `docs/adr/` 或 `docs/decisions.md`；
   - **L3 导航 / 工具链补丁**：修正被带偏的 `AGENTS.md` 导航条目、补齐项目 `verify-*` 校验面或 Skill/脚本缺口；
   - **无需沉淀**：一次性普通 Bug 且代码与回归测试已经说清的，直接写明“已靠测试/代码锁住，无需新增文档”。

## 二、`docs/` 合法居民白名单与四刀自整理法

**代码库是“现状事实”的唯一真相。** 每次显式要求整理 `docs/`，或复盘时发现 `docs/` 混入杂物，按以下唯一标尺巡检：

### 合法居民白名单与标准目录结构（禁止根平铺）

`docs/` 下按职责分目录存放，**禁止把不同类别的文档直接平铺在 `docs/` 根目录**（除单文件 `docs/decisions.md` 或索引外）：

```text
docs/
├── decisions.md        # 单文件决策表（与 docs/adr/ 二选一）
├── adr/                # 独立决策与未决方向（懒创建）
├── ops/                # 部署、发布、签名、基础设施与运维手册
├── guides/             # 面向外部用户/开发者的使用与接入指南
└── contracts/          # 代码无法自解释的外部协议、线格式与领域契约
```

- **懒创建原则**：没有该类文档前不预建空目录；若仓库已有明确子目录惯例则沿用，否则按上述标准归位。
- **移动即全仓改链**：整理归位后必须全局 grep 修正 `README.md`、`AGENTS.md`、CI workflow、脚本、Skill 与文档内部的相对链接，确保 **0 断链**。

### 严禁长期留在 `docs/` 的垃圾
- 一次性过程稿：`*-handoff.md`、`*-retro.md`、`*-research.md`、`*-plan.md`、`*-notes.md`（**例外**：活跃中的跨会话交接草稿统一放 `docs/handoffs/` 并由 `.gitignore` 忽略，任务接手完结后再删，不在使用中误删）；
- 与代码事实冲突或纯复述目录/实现的“现状说明书”；
- 与仓库 `AGENTS.md` 或已有 Skill 内容重复的平行副本。

### 四刀自整理法
1. **删（Delete）**：已结束的交接/调研/计划稿、与代码事实冲突的过时说明书、无意义占位或隐藏杂文件（如 `.DS_Store`）。
2. **提纯（Distill）**：长篇复盘/设计稿里真正影响未来改动的 1–3 条约束或未决方向，抽出来浓缩进 `docs/adr/`（或 `docs/decisions.md`）或机械防线，**然后删掉原长文**。
3. **收口（Close）**：已落地成代码或已放弃的 `proposed` / `open` ADR 更新状态为 `accepted` / `superseded`。
4. **分目录归位与去重（Organize & Deduplicate）**：把根下平铺的散文件归入 `ops/`、`guides/`、`contracts/`、`adr/` 等对应子目录，同主题只留唯一真相源，并全局修完所有引用断链。

## 三、执行边界与输出格式

- **可直接落地**：当前任务范围内显而易见的误导条目修正、新增/收口 ADR、补轻量测试或 Lint 规则；
- **先给清单获准再删**：批量删除历史 `docs/` 文件或修改跨项目公共插件前，先给出带理由的逐文件处置表（保留 / 提纯后删除 / 直接删除），确认后再执行。
- **汇报格式**（只保留非空项，短句直说）：
  - **问题与根因 / 怎么解决的**（附证据指针）
  - **已落地 / 建议落地的结构防线**（标明层级 L1/L2/L3 与验证结果）
  - **`docs/` 巡检与整理清单**（逐文件：保留 / 提纯 / 删除及依据）
  - **Skill / 工具链补丁建议**
