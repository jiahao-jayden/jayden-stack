# Retro（收尾复盘与棘轮固化）

在完成一次非平凡开发、修 Bug 或合入 PR 后运行。**目标不是写一篇没人看的感言，而是把本轮暴露出的摩擦与踩坑永久清零，让下一次同仓库开发更顺。**

## 为什么必须同时看两份证据

- **成品证据**（`git diff`、PR 评审评论、CI/测试报错）：告诉你最终代码里暴露了哪些薄弱点；
- **过程证据**（本轮会话上下文 / transcript 中的反复搜错文件、跑错命令、人工打断纠偏、中途被否决的方案）：`git diff` 里完全看不到这些弯路，只有回看过程才能抓出文档误导、工具缺口与隐性偏好。

## 四项必查与动作（零盘问，直接出可执行清单）

逐项扫描本轮过程证据与成品证据，**没有真实发现的项直接写 `无`，绝不凑数**：

1. **棘轮固化（Ratchet，最高优先级）**
   - 凡是本轮反复踩过的坑、被人工打断纠正过的工程偏好、或 CI/评审抓出来的同类错误，按 [`correct.md`](correct.md) 的防线优先级（**架构消灭 > 类型/Lint 拦截 > 行为测试 > 文档规则**）提出并优先落地能奏效的最高层级防线。
   - 新增规则/检查必须用本轮真实出错案例验过红灯拦截。

2. **清理过时或误导的仓库文档**
   - 回看本轮有没有被某份 `AGENTS.md`、`README.md`、过时脚本说明或失效 ADR 带偏过路。
   - 一旦确认信息已与代码库事实冲突，直接删掉或修正该条错误指引（不补写大段现状说明书）。

3. **高门槛提纯 ADR**
   - 检查本轮是否拍板了满足 [`../../jstack/references/adr.md`](../../jstack/references/adr.md) 门槛的架构取舍或未决方向——特别是**在对话中途否决掉、不会体现在最终代码里的方案**，以及需要收口状态的 `proposed` / `open` ADR。
   - 必须通过反水文自检（“删掉这句，只读代码会不会做错决定？”），不达门槛绝不硬写。

4. **反向打磨 Skill 与工作流**
   - 检查本轮使用的 Playbook、项目专属 `verify-*` skill 或本地快捷脚本是否存在漏测的校验面、多余步骤或工具路径坑。
   - 可逆的小补丁直接给清精确改动；涉及跨项目插件本身的大改则列出最小变更建议供确认。

## 执行与输出规范

- 可逆且落在当前仓库范围的小修（清理误导文档、补缺失的 ADR/状态收口、补测试或简单 Lint 规则）可直接落地并验证；跨模块架构重构或改公共插件配置则先列明方案与影响，不擅自扩大 PR 范围。
- **汇报格式**（只保留非空项，短句直说）：
  - **已落地 / 建议落地的结构防线**（附对应防线层级与验证证据）
  - **清理的误导文档**（文件与删改点）
  - **新增或更新的 ADR**（路径与状态变化）
  - **Skill / 工具链补丁建议**
