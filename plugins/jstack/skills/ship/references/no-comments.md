# No comments（清理废话注释与遮丑代码）

清掉代码里的废话旁白和用长篇注释掩盖的烂设计，而不是把烂代码藏在“重要！勿删！”背后。

## 范围

优先使用调用方指定的文件或 diff；未指定时默认检查相对 `main`（或仓库默认主干）的当前 diff（含工作区未提交改动）。

## 执行步骤

1. **派出 `comment-sicko` 清理注释并标出 `MUST KILL`**：
   - 在 Cursor 中通过 `Task` 派 `subagent_type: "comment-sicko"`；
   - 在 Codex 中按 [`../../../agents/comment-sicko.md`](../../../agents/comment-sicko.md) 的角色规则派专用子代理（严格只删注释和标记，不动业务代码）。
2. **主会话严格复核报告与 diff**：
   - 拒绝任何越界修改业务代码、越出指定范围、误删豁免项（License / 无法修改的外部平台怪癖 / 对外公共 API 文档 / RFC 链接）的操作；
   - 对我们自己代码里的怪癖标记为 `MUST KILL` 的条目保持有效，绝不把注释恢复回去糊弄过去；
   - 复核遗漏的 `eslint-disable` / `@ts-ignore` / `@ts-expect-error` 等抑制注释——凡是压制真实正确性或安全规则的抑制一律列为 `MUST KILL`；
   - 面对薄弱的 `IMPORTANT` / `do not remove` 删留争议，先追调用链或跑 `/why` 查历史：查实属于“无法改动的外部怪癖且在当前活路径生效”才恢复，否则坚决删掉。
   - 若子代理报告严重不合规，回退并点明失败原因重跑一次；连续两次不合规直接停下报错。
3. **处理确认有效的 `MUST KILL` 重构点**：
   - 简单清晰的（删死路径、去多余参数、换用正确 API）直接改掉；
   - 需要调整结构或边界的，先跑一次 **architect** 定形状，再按最小根因修复落地，彻底删掉对应 workaround（不借机扩大范围，也不打症状补丁）。
4. **按三分法处理声称存在约束或架构原因的注释**（如“不要改措辞”、“千万别删，否则 X 会挂”、“为什么不用 Y”）：
   - **能机械化锁住的约束** → 固化为类型、运行时断言、行为测试或 Lint 检查（见 [`correct.md`](correct.md)），然后删掉文字注释；
   - **跨模块架构约束、被否决方案或不可破前提**（代码里看不出来、删了后人会做错决定，且踩中 [`../../jstack/references/adr.md`](../../jstack/references/adr.md) 门槛）→ 升格沉淀进 ADR，删掉散落在代码里的长篇说教；
   - **无法改变的外部平台/依赖/协议怪癖**（且仍在活路径生效）→ 保留精炼一行说明（附外部链接或证据），其余一律删掉。
5. **汇总汇报**：删除注释数、恢复条目数、重跑次数、`architect` 简图、已落地的根因修复、结构化固化项、升格为 ADR 的条目以及未强制约束清单。
